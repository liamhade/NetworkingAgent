# Plan: conventional repo layout, ready to make public

## Why

The app lived one level down in `networking-agent/`, next to workspace leftovers at the repo
root. Hosts (Railway, Render, Fly) look for a `Dockerfile` at the root, so the deploy needed a
"Root Directory" setting, and the repo tracked files that must not be public.

## Layout after

```
Dockerfile  .dockerignore  .gitignore  .env.example
README.md   AGENTS.md      TODO.md
backend/    frontend/      research/    docs/
.claude/skills/  .vscode/launch.json
```

- Everything in `networking-agent/` moves up one level (`git mv`-style renames, history kept).
  `networking-agent/docs/*` and the old root `docs/` (UI drafts) merge into one `docs/`.
- `networking-agent/AGENTS.md` (service-oriented folders, Conventional Commits) merges into the
  root `AGENTS.md`. The old root `README.md` (a three-line list of data sources) is replaced by
  the app README.
- `config.py`: `PROJECT_DIR` is now the repo root, so the default `DATABASE_DIR` becomes
  `PROJECT_DIR / "database"`: the same folder on disk as before. `.env` is read from the root.
- `.env.example` documents every variable with no values.

## Removed from git (kept on disk, now ignored)

| Path | Why |
|---|---|
| `database/` | Per-user data: `search_params.json` holds a real resume summary |
| `progress_dashboard.html`, `.claude/pm-decisions.json` | Local project-manager state, regenerated by the skill |

No API keys were ever committed (checked the full history for Anthropic, Supabase JWT,
Serper/SerpApi and USAJOBS key patterns). `database/users/TEST_USER/*.json` is still in past
commits; removing it from history needs a rewrite (`git filter-repo --path database --invert-paths`)
and a force-push, which is the owner's call.

## Deploy

Railway: clear the service's Root Directory (back to the repo root). `docker build .` at the
root works as before.
